# Форма Света repo-grounded audit (2026-04-07)

## Executive summary
- Проект уже имеет сильный каркас для content-driven каталожного сайта: единая layout-обвязка, data-layer в `src/data/*`, переиспользуемые формы и событийную аналитику.
- Основной риск production-ready уровня сейчас не в визуале, а в операционном контуре: формы пока не отправляют данные в backend/CRM (console-only), в download flow нет реальных файлов, а SEO pipeline частично ручной.
- Есть важные несоответствия в воронке и маршрутизации: в хедере есть ссылки на несуществующие роуты коллекций, query-параметры каталога из меню не применяются, canonical/json-ld почти не используются на страницах.
- Редизайн и смысловая переработка уже видны, но им мешают placeholder-изображения и mixed state (часть страниц зрелая, часть воспринимается как staging).

## Что уже хорошо

### 1) Архитектура и контентный слой
- Данные отделены от UI в `src/data/*`, а типы в `src/types/index.ts` поддерживают будущую миграцию на CMS.
- Маршруты и страницы организованы прозрачно (`src/App.tsx` + `src/pages/*`), есть lazy-load всех вторичных страниц.
- `PageLayout` централизует title/description/canonical/json-ld, что задает правильную основу для SEO-пайплайна.

### 2) Frontend/UI
- Сильная компонентность: `Section`, `PageHero`, карточки, единый `LeadForm`, повторное использование CTA-структур.
- Мобильный CTA-бар и cookie-banner уже встроены глобально.
- В каталоге реализована двухвходовая логика (по коллекции / по задаче), что полезно для проектной воронки.

### 3) Воронка и аналитика
- Событийная модель определена централизованно (`src/lib/analytics.ts`), включая primary/secondary/mid-funnel цели.
- UTM-параметры захватываются и приклеиваются к форме (`src/hooks/use-utm.ts`, `src/components/forms/LeadForm.tsx`).
- Есть базовый антиспам (honeypot) и обязательный consent-блок в форме.

### 4) Legal / trust layer
- Есть набор юридических страниц: privacy/cookies/consent/terms и баннер согласия.
- robots/sitemap присутствуют, базовый SEO-каркас в `index.html` уже добавлен.

## Проблемы и риски

### P0 (критично до полноценного запуска)
1. **Формы не интегрированы с backend/CRM**
   - `LeadForm` по умолчанию делает `console.log`, а не сетевой вызов.
   - Некоторые формы также логируют payload локально (`PriceRequestForm`, `RequestProjectForm`).
   - Риск: потеря лидов при боевом трафике.

2. **Нарушения в routing/IA относительно навигации**
   - В Header есть ссылки на `/collections/ston-classic`, `/collections/ston-texture`, `/collections/lira-garden`, но такие роуты отсутствуют в `App.tsx`.
   - Категорийные query-параметры в header (`/catalog?category=...`) не читаются `CatalogPage` (состояние фильтров инициализируется локально, не из URL).
   - Риск: пользователь попадает в тупики или «не ту» выдачу.

3. **Не завершен production content layer**
   - Большая часть изображений — `/placeholder.svg` в товарах/проектах/статьях/сценариях.
   - Download-блок для архитекторов показывает «Скачать», но это только событие аналитики без файла/гейта.

### P1 (важно для конверсии и поискового трафика)
1. **SEO pipeline реализован не до конца**
   - `PageLayout` поддерживает canonical/json-ld, но страницы почти не передают эти поля.
   - sitemap статический и без динамических product/project/blog URL.
   - OG image и verification в `index.html` оставлены как заготовки.

2. **Конверсионный UX местами не доведен**
   - Непоследовательность CTA-лексики: «Запросить проект», «Обсудить проект», «Получить консультацию», «Связаться» без четкой иерархии по этапам воронки.
   - В `RequestProjectForm` шаги валидируются минимально и без явной индикации ошибок на шаге.

3. **Аналитика не доведена до page-level картины**
   - Есть типы событий `page_view/product_view/project_view/article_view`, но в коде страниц нет системного page-view tracking.

### P2 (техдолг / polishing)
1. **Незавершенности и потенциальные ошибки в frontend-коде**
   - В `ProductPage` есть лишний закрывающий `</ul>`, это риск для стабильности сборки/рендера.
   - Есть legacy-ощущение дублирования слоя CTA (`components/layout/CTASection.tsx` и `components/sections/CTASection.tsx`).

2. **Тексты и бренд-вокабуляр**
   - В целом tone соответствует premium/architectural, но встречаются «скоро»-плейсхолдеры и «технические» формулировки, которые снижают доверие на ключевых страницах.

## Что делать дальше

### Быстрые улучшения (1–3 дня)
1. Привести в соответствие навигацию и фактические роуты:
   - либо добавить страницы деталей коллекций,
   - либо заменить ссылки в mega menu на существующие маршруты/anchor-секции.
2. Сделать URL-driven фильтры каталога (`category/texture/height/sort`) через `searchParams` и двустороннюю синхронизацию.
3. Выровнять CTA vocabulary (главная цель: «Обсудить проект»), оставив вторичные CTA контекстными.
4. Добавить явные error-hints в multi-step форме заявки на проект.

### Средние улучшения (1–2 недели)
1. Подключить реальную form delivery:
   - backend endpoint (или edge function) + retries + логирование ошибок,
   - адаптеры в CRM/почту,
   - единая контрактная схема payload и server-side валидация.
2. Доделать gated downloads:
   - выдача материалов после формы (одноразовые ссылки / email flow),
   - события `download_pdf` привязать к факту успешной выдачи файла.
3. SEO-полировка:
   - canonical и json-ld для ключевых шаблонов,
   - динамическая генерация sitemap из data/CMS.

### Системные/архитектурные улучшения
1. Перевести data-layer на CMS/API без ломки текущих типов (`src/types/index.ts` уже пригоден как контракт).
2. Вынести navigation/content config в отдельный слой, чтобы исключить рассинхрон menu↔routes.
3. Сделать observability для лид-флоу:
   - funnel dashboards по событиям,
   - алерты при деградации отправки форм,
   - event schema versioning.

## Если продолжать работу прямо сейчас

### Наиболее логичный следующий пакет
**Подсистема: Lead & Conversion Reliability (P0/P1).**

Порядок:
1. URL-consistent routing + fixed nav links.
2. Backend delivery для всех `LeadForm`-основанных сценариев.
3. Gated downloads для страницы «Для архитекторов».
4. QA-пакет: smoke-тесты форм/роутов + ручная проверка UTM, consent, analytics goals.

### Почему именно это
- Проект уже достаточно зрелый визуально, но без надежной доставки заявок и корректной маршрутизации текущий редизайн недомонетизируется.
- Это даст максимальный прирост к production-ready качеству без «полного переписывания».
