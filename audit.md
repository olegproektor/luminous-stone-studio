# Аудит текущего репозитория STŌN

## Область аудита
- Проанализированы структура проекта, маршруты, страницы, layout, навигация, ключевые компоненты, данные, формы, аналитика и SEO-обвязка.
- Код не изменялся. Добавлен только этот файл.

## 1) Текущая структура сайта и страниц

### 1.1 Техническая структура
- Стек: `React 18 + Vite + TypeScript + Tailwind + shadcn/ui`.
- Структура по слоям:
  - `src/pages` — маршрутные страницы.
  - `src/components/layout` — каркас (Header/Footer/PageLayout/PageHero/Section).
  - `src/components/sections` — секции главной.
  - `src/components/forms` — форма-лидогенерация.
  - `src/components/ui` — карточки + набор UI-компонентов.
  - `src/data` — контент в коде (products/projects/articles/faq/collections).
  - `src/types` — доменные типы.

### 1.2 Карта маршрутов (React Router)
- Основные: `/`, `/collections`, `/catalog`, `/projects`, `/for-architects`, `/custom`, `/materials`, `/about`, `/blog`, `/faq`, `/contacts`, `/request-project`.
- Детальные: `/catalog/:slug`, `/projects/:slug`, `/blog/:slug`.
- Юридические: `/privacy`, `/cookies`, `/consent`, `/terms`.
- Служебный: `*` (404).

### 1.3 Структура главной страницы
- Главная — длинный лендинг из 14 секций:
  - Hero, Advantages, AboutProduct, Collections, Scenarios, FeaturedProducts, Projects, Architects, Process, Custom, Materials, Trust, FAQ, FinalCTA.

### 1.4 Структура внутренних страниц
- Продуктовые и контентные страницы строятся на комбинации:
  - `PageLayout` + `PageHero` + `Section` + финальный `CTASection`.
- Паттерны:
  - Каталожные листинги с фильтрами (`CatalogPage`, `ProjectsPage`, `BlogPage`).
  - Детальные страницы с breadcrumbs (`ProductPage`, `ProjectDetailPage`, `BlogPostPage`).
  - Лид-страницы с формами (`RequestProjectPage`, `ContactsPage`, `CustomPage`, `ForArchitectsPage`).
  - Юридические long-form страницы.

## 2) Текущая навигация и layout

### 2.1 Header
- Desktop: фиксированный header с анимируемым состоянием при скролле.
- Mega-menu для двух разделов (`Коллекции`, `Каталог`), включая подпункты.
- Mobile: off-canvas меню с drill-down.
- Присутствует переключатель темы и CTA-кнопка.

### 2.2 Footer
- 3 колонки контента: бренд, навигация/информация, контакты.
- Отдельные ссылки на юридические страницы.

### 2.3 Глобальные слои
- На уровне App всегда подключены:
  - `CookieConsentBanner` (fixed bottom),
  - `StickyMobileCTA` (fixed bottom, mobile).

### 2.4 Базовый layout
- `PageLayout` централизует:
  - `Header/Footer`,
  - `<main>`,
  - `title`, `description`, OG title/description, canonical, JSON-LD cleanup.
- Важно: `canonical` и `jsonLd` поддерживаются компонентом, но фактически не передаются страницами.

## 3) Ключевые компоненты и шаблоны

### 3.1 Layout-шаблоны
- `PageLayout`, `PageHero`, `Section`, `CTASection` (layout).

### 3.2 Карточки

## 5) Что не соответствует новой целевой структуре сайта

Ниже — ключевые расхождения, которые мешают переходу к более цельной и управляемой структуре:

- Несоответствие маршрутов и навигации:
  - в header есть ссылки на `/collections/ston-classic`, `/collections/ston-texture`, `/collections/lira-garden`, но таких маршрутов нет.
- Несоответствие семантики фильтров:
  - в header используются `?category=garden` и `?category=accent`, тогда как данные используют `garden-light` и `accent-light`;
  - `CatalogPage` вообще не читает query-параметры для инициализации фильтров.
- Не реализована настоящая иерархия коллекций:
  - есть `slug` у коллекций, но нет страниц коллекций;
  - `CollectionCard` ведет на общий `/collections`, а не на detail.
- Конверсионные и контентные действия частично имитационные:
  - формы в основном отправляют в `console.log`,
  - “Скачать” на `ForArchitectsPage` только трекает событие без файла.
- SEO-функции частично недоиспользованы:
  - `canonical/jsonLd` в `PageLayout` не применяются страницами.

## 6) Дубли, лишние секции, слабые места UI/UX и точки усложнения

### 6.1 Дубли и лишние сущности
- Найдены неиспользуемые секции:
  - `AudienceSection.tsx`,
  - `components/sections/CTASection.tsx` (дублирует смысл `components/layout/CTASection.tsx`).
- Найден объемный “запас” UI-компонентов:
  - из `62` файлов в `src/components/ui` фактически используются примерно `25`,
  - остальное создает шум и повышает когнитивную сложность.
- `NavLink.tsx` и `layout/Grid.tsx` выглядят неиспользуемыми.

### 6.2 Слабые места UI/UX
- Главная очень длинная, с большим числом похожих блоков “карточки + CTA”:
  - есть риск утомления и размытия приоритетов.
- Повтор CTA на многих уровнях без явной иерархии сценариев (request/consult/call).
- Мобильный fixed-слой усложнен:
  - одновременно используются cookie-banner и sticky mobile CTA в нижней зоне.
- Непоследовательная навигация:
  - часть переходов через `Link`, часть через `<a>` для внутренних путей.

### 6.3 Точки архитектурного усложнения
- `RequestProjectForm` дублирует часть логики ввода поверх `LeadForm` (двухэтапный режим), что повышает стоимость изменений.
- React Query подключен глобально, но фактически не используется для данных.
- Аналитика покрывает в основном формы/клики; события `page_view`, `product_view`, `project_view`, `article_view` не задействованы.
- Контент почти полностью на placeholder-изображениях; визуальная ценность продукта пока не раскрыта.

## 7) Поэтапный план рефакторинга (без переписывания с нуля)

## Этап 0. Фиксация целевой IA (1 итерация)
- Утвердить целевую карту сайта и приоритетные пользовательские сценарии.
- Зафиксировать “must-have” маршруты и “optional” маршруты.
- Результат: единый документ IA + routing matrix.

## Этап 1. Приведение маршрутов и навигации в соответствие (P0)
- Синхронизировать header/footer/menu со списком реальных маршрутов.
- Решить судьбу коллекций:
  - либо добавить `/:slug`-страницы коллекций,
  - либо убрать deep-links из header.
- Поддержать query-параметры каталога (`category`) и привести ключи к единому словарю.
- Результат: отсутствие “псевдоссылок” и предсказуемая навигация.

## Этап 2. Консолидация шаблонов и снижение дублирования (P1)
- Убрать/изолировать неиспользуемые секции и UI-заготовки.
- Унифицировать CTA-слой:
  - один базовый CTA-компонент/паттерн,
  - четкая иерархия CTA по страницам.
- Упростить `RequestProjectForm` вокруг `LeadForm` без повторения полей/разметки.
- Результат: меньше поверхностей поддержки, выше скорость изменений.

## Этап 3. Конверсия и данные (P1)
- Подключить реальный submit-пайплайн форм (CRM/webhook/API).
- Реализовать настоящие download-flow для архитекторов.
- Доработать событийную модель аналитики (page/detail/list events + funnels).
- Результат: измеримая воронка и рабочие бизнес-действия.

## Этап 4. Контент и визуальная достоверность (P1)
- Заменить placeholder-ассеты на реальные продуктовые/проектные изображения.
- Сократить шум на главной, сфокусировать секции вокруг 2–3 ключевых сценариев.
- Результат: рост доверия и читаемости УТП.

## Этап 5. SEO и эксплуатационная готовность (P2)
- Внедрить per-page `canonical/jsonLd`.
- Обновлять sitemap динамически для product/project/blog detail.
- Проверить robots/metadata и юридические даты обновления.
- Результат: улучшение индексируемости и релизной зрелости.

## Приоритеты запуска работ
- Сначала: Этапы 0–1 (структура и маршруты).
- Затем: Этапы 2–3 (дубли + конверсия).
- После: Этапы 4–5 (контент + SEO-операционка).
